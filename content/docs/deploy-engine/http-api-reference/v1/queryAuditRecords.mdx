Read the audit trail of actions taken through the Deploy Engine, narrowed by the
supplied filters.

Records come back oldest first, ordered by timestamp and then by ID. That ordering is
what makes extraction resumable: ship a page, then ask again with the `nextCursor`
the response gives you, until `hasMore` is `false`. Resuming on the timestamp alone
would not do, since several records can share one and `limit` is applied after
ordering, so a second holding more records than the limit would never be read past.

Only actions that can change something are recorded. Reads, including the ones in this
section, are not part of the trail.
