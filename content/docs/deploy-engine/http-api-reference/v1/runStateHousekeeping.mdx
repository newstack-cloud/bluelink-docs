Start the upkeep the state backend needs on its own storage, beyond the
retention periods applied by the other cleanup endpoints. What housekeeping
involves is up to the storage engine the Deploy Engine is configured with.
For example, the `objectstore` storage engine writes a change to a blueprint
instance as several objects, so a write that is interrupted part of the way
through can leave objects behind that nothing else would delete, and its
housekeeping reclaims that storage.

Housekeeping never changes what the Deploy Engine reads back, and leaves alone
anything recent enough to belong to a write still in progress, so it is safe
to run at any time, including while other Deploy Engines share the same
state backend.

With a storage engine that needs no housekeeping, such as `memfile` or
`postgres`, the operation completes with `itemsDeleted` set to `0`, so callers
do not need to know which storage engine is in use. The Deploy Engine also runs
housekeeping on its scheduled cleanup interval for storage engines that need it.
